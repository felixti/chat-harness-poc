Architecture · Chat Harness PoC

One turn runner, two entrypoints

The company chat on AKS: Envoy signs users in, chat-api streams each turn, and chat-worker runs scheduled tasks and deep research from jobs leased in FerretDB. Both run the same turn and record the cost of every run.

The headline

Same turn in the chat and in the background

chat-api streams a turn over SSE while the user watches. chat-worker claims a job with an atomic findOneAndUpdate, renews a 90 s lease, and runs the same turn for a scheduled task or a research step. Every model call carries the job id as runId, so each run shows its own cost and stops at its cap.

Trust boundaries

  • Envoy is the only ingress and sets x-user-oid from the Entra token.
  • The LLM gateway injects the OpenRouter key; the pods never hold it.
  • Connector tokens and memory are sealed per user (AES-256-GCM).
  • Default-deny NetworkPolicy; port 443 out only to public IPs.

Not drawn here

  • parser, brave-mcp, chat-pg and the nightly memory-curator: see the network detail.
  • Secrets: Key Vault → External Secrets → read-only files.
  • Delivery: GitHub Actions + Trivy → GHCR → Argo CD.
