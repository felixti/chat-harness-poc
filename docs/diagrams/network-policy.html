Network policy · Chat Harness PoC

Who may open a connection to whom

Namespace chat starts from default-deny for ingress and egress. Each row is a pod that opens a connection; each column is a destination and its port. Every allowed cell is one rule in deploy/networkpolicy.yaml; every pod may also reach kube-dns on port 53.

The headline

Envoy is the only way in

chat-api accepts port 8080 only from the public Envoy Gateway pods, which sign the user in with Entra and overwrite x-user-oid from the token. No other pod, and nothing outside the cluster, can call chat-api directly. chat-worker has no ingress at all.

Pods that never call out

  • parser converts documents with egress: []: a hostile file cannot reach the network.
  • chat-pg answers only FerretDB on 5432 and opens nothing.
  • Only brave-mcp holds the Brave key; the chat reaches it over MCP.

443 out, public IPs only

HTTPS egress is 0.0.0.0/0 minus 10/8, 172.16/12, 192.168/16 and 169.254/16: Blob (service endpoint), Entra, OpenRouter through the gateway, CrawlForge and per-user connectors. Model calls go through the LLM gateway on 10080, which injects the key.
